# 普通文件传输修复报告

## 范围

依据文件传输与断点续传审核清单实施；gpt-6-luna/max 子代理负责产品代码，主控制定合同、复核和执行验收。保留工作区此前的通话、会议、文档及构建产物改动。本次没有部署、提交或推送。

## 已实现

- 新增协商启用的文件 v2 引擎，普通发送入口已接入；旧端继续使用修复后的兼容路径。
- 进度与速度以接收端确认的唯一持久字节计算，排队量单独统计，停止或完成后速度归零。接收、重组、在途数据与哈希并发均有边界，避免把本地排队速度展示成网络吞吐。
- 同一任务按缺块分配 P2P 与服务器两路，共享总窗口；断路重排未确认块，保留任务 ID 和已提交内容。不会同时启动两份完整文件来冒充加速，也不承诺任何网络下两路一定更快。
- 接收分块在 IndexedDB 事务完成后才确认；完整覆盖、块与整文件 SHA-256 校验、历史保存成功后才完成。保存失败保留内容并给出可恢复提示。
- 任务、检查点和取消终态持久保存。双方刷新后恢复原任务，发送端重新选择完整内容相同的原文件即可补传；错误源文件拒绝。对方暂停时显示等待，只有暂停方能继续；迟到消息不能解除暂停或复活取消任务。
- 后端增加参与者/房间授权、帧与元数据校验、有界磁盘暂存、检查点释放、过期清理及重启重建；默认每任务64MiB、总512MiB暂存。免费/PRO限制沿既有权限执行。
- 删除历史使用先停任务、提交历史删除、再清理字节的顺序；失败不能使文件链接提前失效或让已删任务复活。

## 界面约束

默认展示文件名、对方、已确认进度、传输速度及简单状态。线路、排队量、完整任务编号和保存期限收进折叠详情。短断线与单路径可恢复错误自动处理，不弹全局错误、不强制打开面板；只有源文件重选或实际存储/校验失败才突出操作。

## 证据边界

- 浏览器实测是本机可见 Edge/Chrome 与本地服务器；最大单文件36MiB。没有据此宣称中国/新加坡真实跨NAT成功率、3GiB实传或任何网络100%成功。
- 390px仅验证布局，实体手机、Safari、Firefox性能与恢复行为仍需对应设备验证。
- 后端重启恢复由 Go 磁盘重建测试证明，浏览器刷新验收期间后端进程保持运行。
- 取消场景在首个256KiB确认时通过已有API暂停，再从真实界面取消并刷新；活跃写入时的取消竞态另外由定向引擎测试覆盖。
- 本次不新增应用层文件端到端加密。SHA-256负责内容身份与完整性，不等于加密；沿用现有通道保护和服务器可见性边界。
