# 会议加入诊断进度

- 兼容性补强：旧版 WebRTC 优先使用前缀构造器、旧式采集 API、ICE 状态和无 transceiver 时的数据通道占位；权限请求超时后释放队列，迟到轨道停止；关键能力不可用或发布初始化失败时清理成员并显示错误。入会状态只接受服务器确认，避免媒体连接抢先标记成功。
- 本地真实 Edge/Chrome + SFU 验证：模拟旧 API 缺失和旧回调采集后双向收到音频轨；模拟权限不响应后仍留在会议、可重新请求；模拟 WebRTC 初始化失败后显示兼容提示并清理成员；首次确认丢失恢复、持续丢失超时清理通过。模拟不能替代旧版浏览器或 Safari/手机真机验证。
- 验证：42 项针对性测试、TypeScript、目标 ESLint、Vite 生产构建通过。先前既有 no-media E2E 的不一致尚未修正；本次未部署。

- 独立 Edge 与 Chrome 本地会议可正常加入、互相看到；人为悬置麦克风请求时客户端仍可收到入会确认及成员列表。
- 已复现切换不存在的会议时，先前会议的无频道心跳错误被误判为当前会议加入失败；错误限流还可能丢掉 404，使界面停在加入中。
- 用户设备、浏览器和网络环境尚待确认；不能将用户现场问题断言为同一原因。
- 已改：加入回包未到达时等待 12 秒后重试，仍无确认时显示连接失败并退出；加入阶段忽略独立心跳/媒体状态错误；不存在及格式无效的会议使用原有结果页；移除授权等待横幅，保留实际设备错误和重试。
- 验证：独立 Edge/Chrome 与本地 SFU，故意丢弃首次加入确认和成员快照后复现“其他人看得到、本端卡住”，重试后恢复成员及计时；持续丢弃时验证超时提示和服务端成员清理。麦克风请求被模拟悬置或拒绝；主会议、失效分组链接及分组创建/召回路径通过。
- `meetingP0`、`meetingNetwork`、`meetingInvite` 33/33 通过；TypeScript、目标 ESLint、Vite 生产构建通过。
- 既有 `meeting-no-media.e2e.mts` 失败：HEAD 中该测试将摄像头和麦克风默认设为关闭，却期待自动采集后的 not-found 错误；本次新增浏览器测试覆盖实际拒绝权限后的提示。真实用户设备与网络尚未复现；未部署。
