# 会议纪要、字幕翻译与会中提问

## 已获用户确认的产品约束

- 会议纪要默认可用但关闭；主持人控制，参会者知情并可拒绝贡献声音。会中摘要与逐字稿面向全体参会成员共享。
- 逐字稿与纪要在每位成员设备自动保存，服务端不得将会议文字、音频、问题或译文持久化到文件、数据库或日志；断线、离会、浏览器存储失败时诚实显示本地副本可能不完整。
- 新增独立悬浮字幕翻译面板，样式、色彩和交互遵循 `DESIGN.md`；中文→英文、英文→中文，仅双语字幕，不进行语音播报。翻译历史应可通过片段 ID 打开对应会议纪要文字记录。
- 字幕显示及目标语言属于个人选择；字幕、纪要、问答共用经过同意的转写来源，各功能的开始/停止互不误导。仅字幕模式不持久化逐字稿。
- 会议内容问答默认个人可见，限定为会议相关只读问答，答案标明可回溯原文；不能把会议文本当作命令，也不默认创建外部动作。
- 免费优先：不要求用户配置密钥；不得隐藏付费回退或在无法保证免费额度时自动产生费用。模型及翻译额度、认证、上游留存及浏览器 ASR 可用性必须如实体现，不能声称无限免费或整个识别过程都在本机。
- 与现有聊天、媒体和会议管理兼容；不提交或部署，不读取、输出或复制任何实际密钥。

## 设计边界

- 始终把房间身份、主持人权限、成员同意、静音联动与转写来源管理放在 UI 之前；服务端仅临时中继经过校验的数据，不落盘。
- 悬浮面板的历史记录与纪要逐字稿通过同一稳定片段 ID 关联；引用不存在时不虚构可跳转位置。
- 内置模型及翻译服务须有受限接口、限额和不记录正文的日志；现有通用无鉴权代理和会记录原文的 Serverless 不能不加保护直接公开复用。
- 非连接成员、加入较晚或提前退出的成员不保证获得完整历史；本机持久化失败必须明确提示，不影响会议和实时字幕。
- 本机仅保存纪要会话，不因单独开启字幕而持久化完整文本。浏览器语音识别或上游服务可不可用要明确降级。

## 独立审查与修复记录（GPT-6.1-Terra max）

审查结论：初审不建议上线，列出 11 个 P1 与 3 个 P2。已修复并可复核的项：

- 录制纪元（recordingId）：只有与本次 `start` 匹配的片段才可持久化；字幕片段永不被事后标记为新纪要；每次开始重置贡献同意。
- 语音采集生命周期：麦克风授权/讯飞握手期间静音可取消；主持人“本机参与转写”开关绑定真实采集门禁；房间切换、重连清空队列与在途 AI 请求。
- 主持人转移：新主持人接续采集与纪要 finalizer，并重新纳入本机已有逐字稿。
- 收尾与离开：离开前先冲刷待发片段；发送端本地先行保存自己已定稿的语句；停止时等待最终整理上限 20s。
- 长会议整理：内置模型按最旧优先的有界批次处理，剩余片段留在队列；上一版结构化摘要保留；超限明确提示而非静默丢弃。
- 会议 AI 服务：小时级可再生的 200 次安全窗、两个上游并发 + 32 等待位、相同译文短时共享与 1 分钟内存缓存；日志不含正文。
- 问答：无有效原文引用的回答不再显示为结论，改为“无法根据已记录的发言确认”。
- 字幕：逐句按实际文本判定中英混杂语言；历史仅调度有界队列，不再出现永久“等待中”；重连后自动重订阅个人字幕。
- 导出：会中导出现在包含完整逐字稿与结构化纪要。

已知未解决（超出本次改动范围，属既有缺陷）：会议 WebSocket 仍接受客户端自报 `uniqId`，知道主持人 ID 的连接可抢占会话。该问题影响所有会议功能，并非本次新增；应在认证层把 `uniqId` 绑定到 JWT/服务端身份并禁止无凭证重绑。
